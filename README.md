# OPNixMGR项目介绍
- 一个便于修改nix配置文件的后端，需要配合WebUI或GTK前端使用

**观看之前你需要了解的**：

1. 程序是由多个逻辑组成的
2. 单行代码统称为条目
3. 多行代码统称为代码块
## 基础逻辑

### 检测逻辑
1.启动时扫描*configuration.nix*文件(后续统称为主模块)内是否有import导入的子模块

例如：
```nix
import ./modules/desktop/kde.nix
```
如果在主模块中发现了类似于上方的条目则会确认子模块是否存在
- 如果子模块真实存在则标记这个子模块加入待检测区域
- 但当子模块不存在时则会被认为这个条目为错误的，将会被注释

2. 接下来会扫描在待检测区域的所有模块(包括主模块)

```nix
xxx.enable = true;
```
或者
```nix
xxx.xxx = {
    enable = true;
};
```
若模块内出现这样的代码则会记录下该条目(或代码块)，也就是例子中的"xxx"

### 显示逻辑

1.将检测逻辑扫描出的所有"xxx"条目输出，同时根据类型判断应该使用什么开关控制

例如：
- 布尔值(ture or false)会使用复选框控制
- 字符串就会给个输入框用于修改

2. 像这样输出的话肯定很多代码块且容易找不到想要修改的代码块，所以还同时支持搜索(关键词搜索+不区分大小写)

### 修改逻辑

在显示逻辑中修改了xxx的布尔值或字符串都会先保存到缓冲区而不是立即写入文件

1. 需要按下"**应用**"按钮确认写入
2. 会弹出窗口显示出修改的所有代码块和条目并再次确认
3. 在弹出的窗口内再次点击"**确认**"就会将改动写入到文件

### **备份逻辑**
- 这是我认为最重要的一个逻辑，保证配置安全

1. 修改逻辑将改动写入进文件时，会将/etc/nixos下的所有被修改过的nix文件连带目录一起备份成一个压缩包并加上时间戳

例如：

当前在/etc/nixos文件夹下"configuration.nix"和"./modules/desktop/kde.nix"被修改了，则备份的压缩包内目录如下：

```text
我是时间戳喵～.tar.gz
│
├configuration.nix
│
└modules
    └desktop
          └kde.nix
```
而别的未被修改的nix文件则不会被添加进备份内

2. 备份包位置
- 自动备份包位于"/etc/nixos/opnixmgr/backup/auto/"内
- 手动备份包位于"/etc/nixos/opnixmgr/backup/custom/"内

3. 自动创建的备份包超过3个时会自动删除过时的备份包，可在备份板块内手动调整为超过x个自动删除过时的备份包 

4. 可以切换到备份板块手动创建备份包，还可以选择需要备份哪些nix文件或全部备份，手动创建的备份包不会被自动删除

5. 默认备份包名是时间戳，你可以自定义备份包的名字(自动备份除外)

### 测试逻辑

当修改并应用时会跑一遍检测命令检测代码是否存在逻辑错误或拼写错误

- 若出现了错误则会自动保存日志
- 同时选择最近的一次备份包回滚

做完这些后会提示代码有错误，请查看日志，正确修改代码后尝试再次运行

注意：日志位于"/etc/nixos/opnixmgr/log/"内

若代码未出现错误则可以选择现在重建系统或手动重建

### 回滚逻辑

1. 可以在应用内找到回滚选项卡并选择对应的时间戳的备份恢复

2. 回滚时会将备份包内的全部文件全部覆盖到"/etc/nixos/"目录下

## 交互

1. 需要配合GTK或WebUI前端操作，安装时可选择

2. 配备了紧急回滚命令，输入"opback"后，会先扫描
```text
/etc/nixos/opnixmgr/backup/
```
目录是否存在"custom"文件夹及"auto"文件夹
- 若二者都存在则询问要选择哪个(自动或手动)
- 若选择了手动备份包则会继续让你选择文件名回滚
- 若选择了自动备份包则会选择使用哪个时间戳的备份包，不输入则默认是最近的一次回滚
